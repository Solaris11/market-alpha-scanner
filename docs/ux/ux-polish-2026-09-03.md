# UX/UI polish pass — audit and applied changes

Branch `work/ux-polish`, off `b177dea8`. Not merged to `main`, not deployed.
Written 2026-09-03 21:15 UTC.

Scope was the six surfaces you named: `/terminal`, `/discover`, `/symbol/AMD`,
`/symbol/IREN` (same route), `/pricing`, and the onboarding/account first run.
No business logic, pricing, auth, entitlement, scanner or DB query behaviour
changed. No new library or asset. Root `package.json` untouched.

## The design language I worked inside

Worth stating, because it constrained every fix. Tailwind v4 is loaded with a
bare `@import "tailwindcss"` — there is no `tailwind.config.*` and no `@theme`
block, so there is zero theme extension and every colour is a stock Tailwind
utility. Custom values have to be arbitrary-value syntax or one of the CSS
variables in `globals.css`. `src/lib/ui/design-governance.ts` documents the
token set (radius: chip 999px / control 0.9rem / panel 1.25rem / shell 1.75rem;
default border `rgba(255,255,255,0.10)`; emphasis `rgba(103,232,249,0.22)`), and
`globals.css` mirrors the radii as `--tv-radius-*`.

I did not do a sweeping token normalisation. The audit found nine distinct cyan
border opacities and eight white background alphas in the discovery workspace
alone, and rewriting them all is a large diff whose only defence is "the
document says 0.22". That is a judgement call for you, not a low-risk change,
and it would bury the fixes below in noise.

## What was measured, not assumed

I checked the clipping claim against production at 375px rather than trusting
the static read. The compare matrix on `/discover`, with only three symbols
loaded:

```
container right edge:  346px
EOG column:            294px → 362px
overflow hidden, scrollWidth 332 vs clientWidth 315
```

16px of the third symbol's column is cut off today, with no scrollbar and
nothing to indicate anything is missing. A compare preset loads up to eight
symbols, where the track total is 8rem + 8 × 4.25rem = 42rem = 672px, so five
whole columns would be unreachable.

The scanner table is the same shape — fixed rem tracks (`2.75rem 5.5rem
minmax(12rem,1fr)` plus 5rem per metric plus 11rem, 980px minimum with six
metric columns) inside an `overflow-hidden` parent, with cells already marked
`sticky left-0` for a horizontal scroll no ancestor provided. **I did not
measure this one clipping.** At 375px the mobile layout does not render the
grid at all (`scrollWidth === clientWidth`), and I could not get a valid desktop
measurement — the browser pane was collapsed and every width read back as 0.
The change is reasoned from the fixed tracks and the orphaned `sticky left-0`,
not from an observation. Treat it as the weakest item here.

An audit finding I retracted before applying it: a proposed high/mid/low colour
legend for the sector heatmap. `PosterHeatmapChart` does
`cell.tone ?? scoreTone(cell.value)`, so a server-supplied tone can be cyan or
violet, and a fixed three-swatch key would assert a mapping the code does not
guarantee. The cells already print their number; what was actually missing was
the unit, so the header now says "Discovery score 0-100".

## Applied — commit `c8ea41c5`, clipping and layout

| Where | What was wrong | Change |
|---|---|---|
| `IntelligenceDiscoveryWorkspace.tsx` compare matrix | 42rem of fixed track in an `overflow-hidden` box; columns silently truncated | `overflow-x-auto` via a new `tv-scroll-x` utility |
| same file, scanner table | fixed rem tracks, `sticky left-0` cells, no scrolling ancestor | same |
| `globals.css` | — | new `.tv-scroll-x`: thin always-drawn thumb, `overscroll-behavior-x: contain` so a horizontal flick does not trigger the browser back gesture |
| `TerminalNav.tsx` + `AccountMenu.tsx` | mobile header account button ran under `main { overflow-x: hidden }` | see below |
| `ActivationRecoveryNudge.tsx` | sat 4px under the bottom nav | reads `--tv-mobile-nav-clearance` instead of recomputing 5.25rem by hand |
| same discovery file | two search controls with byte-identical `aria-label`s | the in-scanner one is named as the filter it is |
| same | heatmap cells print a bare number with no unit anywhere | header states the scale |

The header fix is the one that needed care. The button already carried
`min-w-0`, which was inert because all of its children were `shrink-0` — a 32px
avatar and the plan badge — so the row had an unshrinkable min-content width.
The badge now truncates (`min-w-0 truncate`, full text on `title`) rather than
wrapping, because `globals.css:375-379` sets `word-break: normal` on `span` and
`button` and `text-wrapping.test.ts` pins that rule. Truncation is the only
option that does not fight it.

## Applied — commit `7ca42bf1`, hierarchy and scale

- **`ShellMetric` on the symbol page** rendered its label at `font-black` and
  its value one size smaller at `font-bold`. On a card headed DECISION the eye
  landed on the word, not the decision. The value is now the heaviest element.
- **Both fallback price charts** drew a line with no scale at all. They now
  carry an axis strip — first date, price band, last date — built from the same
  `candles` array `fastShellPath` draws from, so the caption cannot disagree
  with the line. The `MiniVisuals` sparkline gets lo/hi endpoints for the same
  reason.
- **`PosterGauge`** dropped its own label in the empty state, so a three-gauge
  deck with no data rendered three identical unlabelled boxes.
- **`/pricing` plan chips** were block `div`s, so a `rounded-full` pill
  stretched the full card width and wrapped its label into a two-line lozenge
  on a phone. Both are `inline-flex w-fit` now.
- **The premium CTA** was `shrink-0 whitespace-nowrap` carrying a label
  ("Unlock Premium Intelligence") that reaches roughly 250px inside a 271px box
  at 375px, so the longest label overflowed rather than wrapped. Full width
  below `sm`, unchanged above it.
- **Two `md:grid-cols-4` grids** of 90–130 character sentences became
  `sm:grid-cols-2 xl:grid-cols-4`; at the 768px breakpoint each column was
  about 150px, giving two words a line.
- **`/account` had no `loading.tsx`** while nine sibling routes did, despite
  `force-dynamic` and eight DB reads plus a live Stripe call. First-run users
  arriving from the onboarding gate got a blank route transition. It uses
  `TerminalShell`, so `RouteLoadingSkeleton` is the matching chrome.
- **`AccountSection` headers** were the only icon-free headings on a page that
  already imports six lucide icons and uses them elsewhere. The prop is
  optional; four sections pass one.
- **Two `<h1>` elements** on the symbol page; the smaller is now an `<h2>`.

I also added a `loading.tsx` for `/pricing` and then deleted it:
`RouteLoadingSkeleton` renders terminal nav chrome, which is wrong for a
marketing route, and `/pricing` is static anyway.

## Verification

Both had to be run through a workaround, and you should know what it is. The
mounted `node_modules` was installed on macOS — `@esbuild/darwin-arm64` and
`@next/swc-darwin-arm64` are present, the linux-arm64 packages are not — and
neither the bridge VM nor the cloud container can reach the npm registry (403).
So `tsx`, and therefore `npm test`, fail here for platform reasons. TypeScript
itself is pure JS and already installed, so a Node module hook transpiling
`.ts` through `ts.transpileModule` does the same job; it lives in
`frontend/.next/tv-scratch/`, which is gitignored and disposable.

**`next build` has not been run and cannot be run here** — it needs the native
SWC binary. Run `npm --prefix frontend run build` on your Mac before deploying
this branch. Nothing in this diff crosses a server/client boundary (class
strings, one new server-rendered caption component, one `loading.tsx`), but
that is an argument, not a build.

**No after-screenshots.** The changes are not deployed, and a dev server needs
the same SWC binary the build does, so there is nothing running that contains
them. The before-measurements above are DOM reads from production; screenshot
capture also failed, returning blank frames from a collapsed browser pane.

# Second pass — 2026-09-04

## The header overflow, now measured on production rather than reasoned

The first pass fixed the mobile account button from a static reading of the
flex rules. Measured on prod `b177dea8` at 375px, the button's own box:

```
BUTTON  .tv-tap-motion.inline-flex.h-10.min-w-0…   right: 379px   width: 126px
document.documentElement.scrollWidth: 375   (the page does not scroll)
```

Right edge 4px past a 375px viewport, inside `main { overflow-x: hidden }`, so
it is clipped rather than reachable. That is the defect `c8ea41c5` fixes, and
this is its before-value.

## A 375px audit of the whole route, and what is *not* a defect

Eighteen containers on `/terminal` report content wider than their own box
inside a non-scrolling parent. Most of them are not defects, and it is worth
writing down which, so nobody spends a day chasing them:

| Container | scrollWidth vs clientWidth | Verdict |
|---|---|---|
| `.tv-ecosystem-panel` | 1126 vs 349 | **not a defect** — no descendant is wider than the panel; the overflow is its decorative `::before`/`::after` glow layers, which `overflow-hidden` is there to clip |
| `.tv-superplatform-panel` | 884 vs 349 | same |
| `.tv-consciousness-panel` | 423 vs 315 | same |
| `.tv-cinematic-card` (×3) | 489–558 vs 283 | **real** — a `min-w-0` inner box measures 354px inside a 283px card, so roughly 71px of content is clipped |
| mobile header account button | right edge 379 vs 375 | **real** — fixed in `c8ea41c5` |

The distinction is the whole value of the audit. A raw
`scrollWidth > clientWidth` sweep flags 18 things; checking whether any *child*
is actually wider than the container separates clipped content from a glow that
is supposed to be clipped. Three of the six largest numbers are decoration.

The `.tv-cinematic-card` one is left alone deliberately: it is real but small,
and I cannot see the result of a change to it. Fixing 71px of clipping blind,
in a card whose layout I would be guessing at, is how a 71px problem becomes a
broken card. It is written down instead.

## Charts: what the second pass changed

Every chart on the five routes was checked against six questions — title,
scale, legend, hover readout, empty state, and implementation. The
`lightweight-charts` surfaces (`SymbolChart`, `MarketChartHub`) pass all six.
The hand-rolled ones are where the gaps were. Four were fixed, each using data
the component already had:

- **`MiniCandleStrip`** had no title, no numbers anywhere, and `aria-hidden` on
  every bar — decoration a screen reader could not see and a sighted reader
  could not read. Now: a label, first-to-last percentage change, a lo/hi footer
  from the same min/max the bar heights use, and a per-bar title carrying that
  bar's value and its change from the previous bar.
- **`ScoreFactorStrip`** accepted a `detail` on every factor and rendered none
  of them, while callers passed real explanations into it. They render now, and
  the header states the 0-100 scale.
- **`PosterGauge`** drew an arc with no anchor. It says 0-100.
- **`SignalHeatmap`** encoded conviction as colour across four bands with no
  key, and rendered a blank 12rem box when there were no rows. Both fixed; the
  bands moved to `src/lib/ui/conviction-bands.ts` so legend and tiles are built
  from one array and cannot disagree, with six tests.

One accessibility fix outside the charts: the `prefers-reduced-motion` block
covers all 32 animation classes defined in `globals.css`, but Tailwind's own
`animate-pulse` is not gated by the framework, and with no `tailwind.config`
and no `@theme` block there was nowhere else to override it. A reader who asked
their OS for less motion still got a pulsing loading state on `/discover`.

## Animation

The user asked for 150–250ms micro-interactions. The design system already
defines exactly this: `--tv-motion-instant` 90ms, `--tv-motion-fast` 150ms,
`--tv-motion-medium` 260ms, with two easing tokens, and a reduced-motion block
that covers everything. The right move was to use those tokens, not to add new
numbers beside them. The one new interaction — per-bar hover on the candle
strip — sits on `--tv-motion-fast` and is gated to fine pointers so it does not
become a sticky state on touch.
